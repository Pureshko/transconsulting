# Финальное ТЗ: калькулятор сбора за проезд TES

Репозиторий: `Pureshko/transconsulting`
Рабочая ветка для изменений: создать отдельную ветку от актуальной `main`.

## 1. Цель задачи

Привести интерфейс калькулятора к финальным замечаниям клиента, исправить расчет одиночного трехосного автомобиля и корректно учитывать разнесенные оси прицепа.

Не ограничиваться заменой текста. После изменений необходимо пройти весь сценарий для каждого типа транспортного средства, проверить расчет, карточки осей, изображения, PDF и адаптивную верстку.

## 2. Критическая ошибка расчета одиночного автомобиля

### 2.1. Воспроизводимый пример клиента

- Тип ТС: `Одиночный автомобиль`.
- Первая группа: 1 ось, односкатная.
- Вторая группа: 2 оси, двухскатная.
- Нагрузка на первую группу: `8,9 т`.
- Нагрузка на вторую группу: `16,98 т`.
- Расстояние между осями второй группы: диапазон, при котором допустимая нагрузка группы не меньше `16,98 т` (например, свыше 1,3 до 1,8 м).
- Длина: `12,3 м`.
- Ширина и высота: в пределах стандартных значений.
- Маршрут: `1331 км`.
- Весенние ограничения: выключены.

Текущий результат: около `6 908 ₸`.
Ожидаемый ориентир клиента: `32 тыс. ₸`.

### 2.2. Причина

В `js/calculations.js`, функция `getSingleVehicleAllowedMass()`, калькулятор автоматически применяет допустимую общую массу `26 т`, если:

- у одиночного автомобиля три оси;
- ведущая группа сдвоенная;
- выбрана двухскатная ошиновка;
- суммарная нагрузка ведущей группы не превышает `19 т`.

Это недостоверное упрощение. Норма `26 т` применяется только при условии, что нагрузка **на каждую** ведущую ось не превышает `9,5 т`. Текущая форма принимает только суммарную нагрузку группы и не позволяет проверить каждую ось отдельно.

Из-за автоматической льготы общая масса `25,88 т` считается допустимой, и в сбор попадает только превышение длины на `0,3 м`:

```text
коэффициент длины = 0,3 × 0,004 = 0,0012
сумма = 0,0012 × 4 325 × 1 331 = 6 907,89 ₸
```

При базовом пределе общей массы `25 т`:

```text
превышение массы = 25,88 − 25 = 0,88 т
коэффициент массы = 0,88 × 0,005 = 0,0044
общий коэффициент = 0,0044 + 0,0012 = 0,0056
сумма = 0,0056 × 4 325 × 1 331 = 32 236,82 ₸
```

### 2.3. Требуемое исправление

В `getSingleVehicleAllowedMass()` удалить автоматическое предположение `Y <= 19`, поскольку суммарная нагрузка группы не подтверждает нагрузку на каждую ось.

Базовое безопасное поведение:

```js
if (totalAxles === 3) return MASSES.O2; // 25 т
```

Льготу `26 т` можно применять только после явного подтверждения условия. Предпочтительный вариант:

1. Для одиночного трехосного ТС со сдвоенной двухскатной ведущей группой показать отдельный переключатель:
   `Нагрузка на каждую ведущую ось не превышает 9,5 т`.
2. По умолчанию переключатель выключен.
3. Передать значение через `readFormData()` отдельным boolean-полем, например `singleThreeAxleBonusConfirmed`.
4. Возвращать `26 т` только при включенном подтверждении и подходящей конфигурации осей.
5. При смене типа ТС, количества осей или ошиновки сбрасывать подтверждение.

Не использовать условие `сумма группы <= 19 т` как замену проверке каждой оси.

## 3. Оси прицепа при расстоянии свыше 2 м

Для типа `Фургон + прицеп` расстояние более `2,0 м` между соседними осями означает, что клиент должен внести их как отдельные оси, а не как одну сдвоенную/строенную группу.

### Требуемый UX

1. В диапазонах расстояния для групп осей прицепа последний вариант должен заканчиваться на `2,0 м включительно`.
2. Рядом с выбором расстояния показать пояснение:
   `Если расстояние до следующей оси больше 2,0 м, добавьте ее как отдельную ось.`
3. Для `Фургон + прицеп` сделать кнопку добавления следующей оси заметной и назвать ее `+ Добавить отдельную ось прицепа`.
4. Добавленная ось должна иметь собственные поля:
   - тип/количество осей;
   - ошиновка;
   - нагрузка;
   - расстояние, если пользователь снова создает группу из нескольких близких осей.
5. Значение нагрузки дополнительной оси должно участвовать:
   - в общей фактической массе;
   - в проверке допустимой общей массы;
   - в осевой части коэффициента;
   - в PDF и сообщении WhatsApp.
6. Нельзя молча считать две оси на расстоянии более 2 м одной сдвоенной группой.

Применить это правило как минимум к сценарию `pricep`. Не менять трактовку остальных типов ТС без отдельной проверки, поскольку редакция допустимых осевых нагрузок 2026 года также содержит понятие группы сближенных осей до 2,5 м.

## 4. Текстовые изменения интерфейса

### Боковая навигация

- `Вес и габариты` → `Вес и габариты транспортного средства`;
- `Маршрут` → `Маршрут перевозки`;
- `Расчет и результат` → `Расчет суммы сбора за проезд`.

Исправить одинаковые названия во всех местах: боковая панель, мобильный прогресс, заголовки шагов и финальный экран.

### Карточки транспортных средств

- `Тягач + трал (модульный трал)`: добавить подпись `(модульный трал)`.
- `Тягач + прицеп` переименовать в `Фургон + прицеп` во всем интерфейсе, PDF и WhatsApp.
- Для `Одиночный автомобиль` описание заменить на:
  `Грузовой автомобиль без прицепа или спецтехника (автокраны, миксеры и другие)`.

### Названия осей и ошиновки

Во всем калькуляторе формы должны отвечать на вопрос `Какая?`:

- `Одиночная` → `Одиночная`;
- `Сдвоенная` → `Сдвоенная`;
- `Сдвоенная с ленивцем` → `Сдвоенная с ленивцем`;
- `Строенная` → `Строенная`;
- `Четырехосная` → `Четырехосная`;
- `Односкатная или смешанная` → `Односкатная или смешанная`;
- `Двухскатная` → `Двухскатная`.

Сохранить смысл выбора: `односкатная или смешанная` должна по-прежнему использовать консервативный лимит односкатной группы.

### Названия секций по типам ТС

- Для трала `Сложная конструкция — группы осей на прицепе (трале)` заменить на `Модульный трал`.
- Для полуприцепа использовать `Группы осей на полуприцепе`.
- Для `Фургон + прицеп` первую прицепную группу назвать `Первая ось на прицепе`.
- Не показывать для `Тягач + полуприцеп` текст о передней распределительной тележке.

## 5. Изображения и карточки

Использовать комплект изображений из ссылки клиента, указанной в исходном DOCX. Не генерировать произвольные замены, если исходные файлы доступны.

### Общие требования

- Увеличить изображения в карточках без обрезки значимых частей.
- Использовать `object-fit: contain`.
- Убрать серый фон у трала; фон всех карточек должен быть белым.
- Не растягивать растровые изображения по ширине с нарушением пропорций.
- Добавить содержательные `alt`.

### Тягач + трал (модульный трал)

- Увеличить изображение трала в выборе типа и конструкторе.
- В скачиваемом PDF показывать композицию `Тягач + трал (модульный трал)`, а не только прицеп/трал.

### Тягач + полуприцеп

- В карточках рулевой и ведущей группы показывать тягач без полуприцепа с выделением соответствующей группы.
- В карточке осей полуприцепа показывать полуприцеп без тягача.
- В весовых и габаритных параметрах показывать `Тягач + полуприцеп`.

### Фургон + прицеп

- Во всех шагах использовать изображение `Фургон + прицеп`.
- Не использовать изображение тягача с полуприцепом.

### Одиночный автомобиль / спецтехника

- На карточке выбора поочередно менять изображения одиночного грузовика, автокрана и миксера.
- Интервал смены: ориентировочно `3–5 секунд`.
- Учитывать `prefers-reduced-motion`: при включенном снижении анимации оставить статичное изображение.
- При выборе карточки и переходе на следующие шаги использовать изображение, соответствующее одиночному ТС/спецтехнике.
- Изображения автокрана и миксера должны быть локальными файлами репозитория, а не внешними URL.

### Передняя распределительная тележка (Jeep Dolly)

- Заменить изображения `Да/Нет` и изображения рядов тележки на файлы из комплекта клиента.
- Проверить одинаковый визуальный размер и белый фон.
